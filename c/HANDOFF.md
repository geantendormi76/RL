## 4. 🚧 当前卡在哪？（承前启后的战略切入点）

**“模型已经足够聪明且无写盘幻觉，但作为本地操作系统 Agent，它身上带着开源商业模型的安全死锁枷锁！”**
- **核心痛点**：
  `Qwen3-VL-8B-Instruct` 出厂时经过了标准 RLHF 安全对齐。当作为端侧 Agent 处理系统深层文件、敏感业务单据、调用本地 Bash/PowerShell 脚本时，极易因撞上安全护栏而触发拒答死锁（“抱歉，我无法协助处理该请求”）；
- **战略决断**：
  **绝不重新训练模型！** 我们采用当前学术界 SOTA 的 **非匹配多向表示工程消融（Representation Engineering / Abliteration）** 技术，在 CPU 内存或单卡上计算激活残差流，使用正交投影算子将拒答向量从权重中外科手术式剔除。

## 5. 🚀 下一步作战计划：第 4 步——非匹配多向拒答消融（Abliteration）

接手的全新 AI 架构师，必须严格按照 **Petrov (2026) & Joad (2026) 规范**，带领用户执行以下消融手术步骤：

```text
┌────────────────────────────────────────────────────────────────────────┐
│  步骤 4.1：构建 400 条非匹配对比基准 (Unmatched Contrast Bulk)         │
│  - 200 条触发拒答的边界越狱/敏感指令 (Harmful / Sensitive Prompts)   │
│  - 200 条通用日常良性指令 (Benign General Prompts)                    │
│  - 🚨 严禁使用话题匹配（Topic-matched）对照，防止拒答势能相消归零！    │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│  步骤 4.2：残差流激活采样与拒答方向提取 (Residual Stream Probing)     │
│  - 挂载 Qwen3-VL 语言主干，捕获所有中间 Decoder 层的激活张量；         │
│  - 计算平均差分向量: Δh_l = Mean(h_harmful) - Mean(h_benign)；        │
│  - 筛选拒答信噪比最高的核心敏感层（通常位于第 14 ~ 24 层）。          │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│  步骤 4.3：正交投影矩阵擦除 (Orthogonal Projection Abliteration)      │
│  - 对敏感层的 down_proj / o_proj 实施正交投影剔除:                    │
│    W_ablated = W - (W · v) ⊗ v^T   (其中 v 为单位化拒答方向)           │
│  - 保持模型权重 100% 连续平滑，形状守恒，0 量化噪音。                 │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│  步骤 4.4：产物导出与消融验收 (Handoff to llama.cpp)                  │
│  - 保存消融后的纯血 BF16 Safetensors 模型到指定目录；                 │
│  - 验收断言：拒答率降为 0%，同时送货单提取与日常知识能力 0 退化！      │
```

## 6. 🚨 14 条绝对不可逾越的“血泪踩坑铁律”（HARD CONSTRAINTS）

新 AI 必须将以下禁令作为最高铁律无条件执行：

| 编号 | 致命病灶与踩坑史 | 绝对不可违反的铁律 |
| :---: | :--- | :--- |
| **01** | **在 GGUF 上做消融或训练** | **严禁在 GGUF 格式上做任何消融或微调**！GGUF 是只读量化结构，消融手术必须在 PyTorch / Safetensors 浮点态上进行。 |
| **02** | **消融时采用话题匹配基准** | **严禁采用 Topic-matched 基准**！按 Petrov (2026) 论文，必须使用 400 条 Unmatched bulk 对比基准，否则拒答势能被相消归零。 |
| **03** | **量化高清眼球 mmproj** | **严禁将 mmproj 压缩为低比特**！分流导出时 `mmproj` 必须保持 F16（~1.1GB），只对庞大的语言主脑做 IQ3/Q4 量化。 |
| **04** | **消融破坏视觉塔** | **严禁碰触 ViT 视觉塔权重**！拒答神经元仅存在于语言模型的注意力与前馈残差流中，消融手术只对语言层（`model.layers`）操作。 |
| **05** | **盲目使用发散采样 (Temperature > 0)** | 工业票据场景必须锁死确定性贪婪解码（`do_sample=False`），严禁使用随机采样导致字序颠倒或掉字。 |
| **06** | **破坏已闭环的 Rust 18000 端口契约** | `crates/services/*` 中的 10 大算子映射必须保持 100% 稳定，严禁随意重命名已有 API。 |
| **07** | **死管道导致永久假死** | Windows 下子进程 Stdio 通信若遇 broken pipe，必须依靠 `lib.rs` 的自动探活与秒级重启重连机制。 |
| **08** | **PowerShell 落盘转义破坏** | 凡涉及代码写入，**必须强制使用** `Set-Content -Path "..." -Encoding UTF8 -Value @' ... '@` 单引号原样字符串。 |
| **09** | **命令行行首带 `#` 注释** | 严禁命令行以 `#` 开头，防止 PowerShell 执行中断或跳步。 |
| **10** | **一次性倾倒大量长流程代码** | **严格执行单步推进**：每次只给出一个文件的操作或命令，等待用户贴回真实终端输出后，再给下一步！ |
| **11** | **使用偷懒省略代码** | 绝对禁止使用 `// ... 其余代码不变 ...` 等偷懒占位符，所有交付物必须是 100% 全量完整代码。 |
| **12** | **盲改未包含源码文件 (Rule 11)** | 修改未在上下文中全量包含的文件前，必须先输出 `Get-Content <文件路径>` 审阅，严禁盲猜打补丁。 |
| **13** | **盲目从头跑高阶 RL 微调** | 钱学森务实工程准则：基模已在真机上验证达标，绝不浪费显卡盲目炼丹，一切以消融交付为核心。 |
| **14** | **破坏 C:\dev\RL\data 与 models 目录** | `models/Qwen3-VL-8B-Instruct` 与 `data/` 中的真实单据资产神圣不可侵犯，严禁覆盖或删除。 |
